# Activity 2: Code Quality Detective

## Objective

The purpose of this activity was to look at code I had written previously and identify areas where the quality could be improved.

## What I learned

### 1. Code smells can indicate problems

I learned that a piece of code can work correctly and still have problems that make it harder to maintain. These problems are often referred to as code smells. They can include unnecessary repetition, unclear naming, overly complicated logic or functions that are doing too many things.

### 2. Maintainability matters

I learned that code should not only work for the person who originally wrote it. Other developers may need to understand, change or debug it later. Writing clear and organised code makes future changes easier.

### 3. Reviewing older code helps me see my own improvement

Looking at older code helped me recognize things I would approach differently now. It showed me that reviewing previous work is useful because it allows me to identify patterns in my coding and areas where I still need to improve.

## Code Quality Checklist

When reviewing my code in future, I can ask:

- Is the code easy to read?
- Are variables and functions named clearly?
- Is there unnecessary repetition?
- Is each function doing one clear task?
- Is the logic more complicated than it needs to be?
- Can another developer understand the code without extensive explanation?
- Are there possible performance problems?
- Are there edge cases that have not been considered?
- Is the code easy to maintain and modify?

## Reflection

This activity changed the way I look at code. Before, I mainly focused on whether the program worked. I now understand that code quality also includes readability, maintainability, structure and efficiency. Using AI as a reviewer helped me look at my code from another perspective, but I still had to decide whether the suggested improvements made sense.
